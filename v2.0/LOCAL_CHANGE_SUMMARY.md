## 上一轮收尾实现

- Web 与封装/转存 worker 改用独立进程，运行时新增 `worker_runtime.py`。Docker 保留 `python app.py` 入口并包含新模块。
- 页面、本地启动脚本、Docker 镜像版本及 CI 校验统一使用 `VERSION`。
- 正式镜像流程要求手动选择精确的 `v<VERSION>` Git 标签，而且标签必须指向构建提交；从主线或最近的旧标签发布新代码会被拒绝。
- 测试镜像同时提供 `test` 与 `sha-<12位提交号>` 标签，以便固定实机验收版本和回滚；OCI 标签记录开发版本和完整提交号。
- Compose 只引用 Actions 已发布的远端镜像；部署脚本仅拉取和更新 `iso-packer-v2` 服务，依据 Docker 健康检查报告结果。
- 本地安全预览只监听 `127.0.0.1`，禁用自动扫描和启动恢复，并保留禁止真实 CD2 拉取/持续状态轮询的开关。手动文件操作仍然生效，应使用独立测试数据。
- 新增 CD2 全部上传暂停控制：手动暂停/解除、暂停至自定义北京时间、多个每日暂停窗口（支持跨午夜）；计划默认关闭且不预填固定时刻。UI 区分本项目转存门禁与远端上传暂停确认，恢复仅处理本服务认领的任务。
- 修复 PushMessage 具体终态证据丢失、源目录/本机 ISO 替换及 rerun 清理竞态、禁用扫描后仍被 push 触发自动扫描，以及 worker 已退出但健康检查仍返回 200；均有回归覆盖。
- 明确 Finish 可完成旧任务状态，但没有转存时清理归属记录的旧任务不会自动删除源目录和本机 ISO，并保留人工核对警告。

## 本轮逻辑复审（基线 e70d59f）

多 agent 按真实流程复审状态、路由、文件操作、封装/清理和进程生命周期，修复如下：

- 旧版本清理与本次 generation、新 ISO 及旧候选身份绑定；等待云端的任务延后到明确 Finish，期间旧文件被替换则保留。
- 源树逐项 metadata digest 检查文件变化，ISO 持久化生成归属记录（provenance）；Windows 读取真实 `FILE_BASIC_INFO.ChangeTime`，不使用创建时间代替。文件变更时间无法可靠读取时保守保留，不放宽自动清理条件。
- 旧任务或重启恢复时缺少 provenance 的已有 ISO 不自动复用，也不据此自动删除源目录或本机副本，保留文件并提示人工核对。
- 手动确认已上传重验任务 generation，旧确认请求不能完成新任务；并发启动与取消边界避免重复运行或取消后仍收尾删源。
- CD2 pull 不再让已完成子任务冒充整个原盘完成；匹配 Rename 返回的实际目标、失败优先；重新检测清除旧失败 terminal 后仍要求新明确完成证据。
- 手动暂停接管任务 ownership，自动恢复不误恢复用户暂停；控制前复核最新配置、RPC 串行化，快照以单调 revision 接收，防止旧响应回滚状态。
- Web 父进程被意外终止时清理独立 worker、工具进程并释放数据目录 lease。
- 文件操作拒绝显式或父路径中的符号链接，排队后复验源文件/父目录身份及授权根；复制排他创建，同服务文件任务串行，避免误删替换文件或写到根外。
- settings 目录选择器按请求代次丢弃旧响应/错误，切换字段或关闭后不再被旧请求覆盖，读取期间禁止确认目录。

## 仍需 VPS 实机验收

1. Actions 构建测试镜像后，固定 `sha-<12位提交号>`，记录镜像 digest、提交号和验收时间。
2. 离线 1 GiB 合成封装已通过；继续使用真实媒体验证转存、CD2 上传和交付全过程，并持续观察页面与 `/healthz` 响应。
3. 验证 worker 异常退出、服务重启及传输失败时，源文件保留、状态提示与恢复正确。
4. CloudDrive2 API 连接失败或任务暂时不在列表时保持等待；只有 `Completed`/`Finish` 才完成，只有明确 `Failed` 才失败。
5. 确认 TMDB 海报、文件浏览网盘内复制、日志中心和大目录媒体检测正常。
6. 验收通过后，才为同一提交创建正式 Git 标签并手动更新 `latest`。

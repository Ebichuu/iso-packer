# CD2 严格 ISO 转存设计

## 问题

ISO Packer 原先会在 CloudDrive2 挂载目标目录中先创建 `影片.iso.partial`，复制完成后再改名为 `影片.iso`。CloudDrive2 会观察挂载目录中的临时文件，可能把它当作上传对象，并在云端形成 `影片.iso..partial` 一类中断残留。该文件不是 ISO 格式，也不应进入上传队列。

## 方案

1. 本机 `/output` 保留现有 `影片.iso.partial -> 影片.iso` 封装流程，确保未完成封装不会伪装成成品。
2. 转存前要求来源是普通文件、文件名扩展名严格为 `.iso`（大小写不敏感），并通过 ISO 结构校验。
3. CloudDrive2 挂载目标目录只创建最终 `.iso` 路径，不再创建 `.partial` 临时路径。
4. 复制完成后复核目标大小和 ISO 结构；失败时删除本次创建的未完成目标并保留本机来源。
5. CD2 上传队列只接纳目标路径扩展名严格为 `.iso` 的条目。`.iso.partial`、`.iso..partial` 和其他格式不参与任务匹配、进度展示或完成判定。

## 安全边界

- 不修改已经存在的同名目标；同名冲突仍交给现有完整性检查和人工处理流程。
- 只有本次转存新建的失败目标会被清理，不扫描或批量删除用户目录中的其他文件。
- 目标校验成功前不删除 `/output` 来源 ISO。
- `.ISO` 等大小写变体按 ISO 处理；末级扩展名不是 `.iso` 的路径全部拒绝。

## 已有异常文件

`Confessions of a Police Captain ...@OurBits.iso` 和 `Caligula The Ultimate Cut ...@OurBits.iso` 的历史日志均记录了本机 ISO 结构校验通过、CD2 转存大小校验通过和上传队列完成。当前 `00-mkiso` 中只存在正常 `.iso`，不存在同名 `.partial`，因此不做重复封装或破坏性改名。

## 验收

- `.iso` 和 `.ISO` 来源可转存，挂载目录中只出现最终 ISO 文件。
- `.iso.partial`、`.iso..partial`、目录和结构校验失败的伪 ISO 均被拒绝。
- 复制失败、大小不一致或目标 ISO 结构校验失败时清理本次目标并保留来源。
- CD2 上传队列过滤所有非 `.iso` 条目，且不会把它们匹配到正常任务。
- 现有单元测试和冒烟测试全部通过。

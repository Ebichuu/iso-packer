# CD2 大目录候选扫描修复设计

## 问题

CD2 监控根目录 `/115/00-未整理/01-BDMV` 当前有 149 个一级目录。扫描器先列出根目录，再逐个进入影片目录确认 `BDMV` 或 `VIDEO_TS` 结构；单个目录确认需要约 2 到 6 秒，因此 15 秒截止时间只能检查前几项。连接在超时后关闭，后台线程却把已检查出的少量候选连同其余错误当作成功结果缓存，导致目录后段的影片一直不会进入自动拉取。

## 方案

1. 对末级名称明确包含 `BDMV` 或 `VIDEO_TS` 的监控根目录采用快速扫描：一次列出其直接子目录，并按根目录名称推断候选类型，不再逐项读取子目录。
2. 创建拉取任务前继续调用现有的 `cd2_disc_type_for_remote_path()`，只在选中目录真实包含 `BDMV` 或 `VIDEO_TS` 时提交复制任务。
3. 把 CD2 protobuf 时间戳转为标准 UTC 时间字符串，并按修改时间从新到旧排列候选，使自动拉取优先处理最近进入监控目录的影片。
4. 通用监控目录和深层扫描继续使用现有结构探测逻辑。任何子目录读取错误都把本轮标记为不完整；不完整结果不得作为成功缓存，也不得触发自动拉取。

## 安全边界

- 快速扫描只适用于名称明确表达原盘类型的监控根目录。
- 根目录推断只用于候选展示和排序，不替代拉取前的真实结构校验。
- 扫描失败不创建拉取任务，不删除或移动远端文件。
- 已完成、处理中、失败冷却和自动拉取认领规则保持不变。

## 验收

- 一个包含大量影片目录的 `01-BDMV` 根目录只需要一次根目录读取即可返回全部候选。
- 位于目录列表后段的 `Is.This.Thing.On...` 类候选可进入结果并参与自动拉取。
- 自动拉取按修改时间从新到旧选择候选。
- 通用目录仍会检查子目录结构；任一读取错误都会产生失败结果且不会被成功缓存。
- 现有单元测试和冒烟测试全部通过。

# 版本感知异常恢复设计

## 背景

当前封装流程使用源目录名生成输出 ISO 文件名。输出目录中存在已校验的同名 ISO 时，任务会记录 `output_exists` 并等待人工处理。这个保护对完全相同的源目录有效，但不能表达电影洗版版本之间的关系。

远程日志还暴露出另一类问题：同一 CD2 远程路径的自动拉取任务会被重复创建，日志被同一候选持续刷屏。异常恢复卡片则会因为长标题、路径和建议文本缺少有效的最小宽度与任意位置换行而发生横向溢出。

## 目标

1. 同一站点、同一影片的明确版本号按升级关系处理：`V1 -> V2 -> V3`，新版本成功后替换旧版本。
2. 不同站点的同一影片始终并存，例如 `@CHDBits` 与 `@OurBits` 不能互相覆盖。
3. 文件名没有明确独立版本标记时，不参与自动替换，与其他未标注版本和所有 `Vn` 版本共存。
4. 同一 CD2 远程路径和目标目录只允许一个自动拉取认领，直到完成、失败冷却或人工清除。
5. 异常恢复卡片在窄屏和长路径场景下不撑破父容器。

## 非目标

- 不对没有明确版本标记的源目录做内容猜测或自动覆盖。
- 不把不同站点的版本合并成一个媒体任务。
- 不改变现有 ISO 的命名风格；新 ISO 继续保留完整源目录名。
- 不把媒体比对页的展示分组直接用于封装覆盖决策。

## 版本与替换规则

### 版本标记

只识别独立的 `V` 加正整数标记，例如 `V1`、`V2`、`V3`。标记必须与相邻字母和数字分隔，避免把普通标题或编码中的字符误识别成版本号。

- 有明确版本标记：参与版本比较。
- 没有明确版本标记：版本状态为 `unversioned`，不参与自动替换。
- `V0`、无法解析的标记和多个冲突版本标记：视为不明确，不自动替换。

### 同站点媒体身份

替换匹配键由现有片名/年份解析结果和发行站点组成。发行站点取发布名末尾的 `@站点` 标记并做大小写、空白和路径分隔符归一化。

只有满足以下条件的文件才属于可替换候选：

- 片名和年份身份一致；
- 站点标记一致且非空；
- 新旧文件都有明确版本号；
- 新版本号严格大于旧版本号。

发布组、分辨率、音视频规格等信息保留在文件名中，但不单独决定跨版本替换。这样同站点的洗版可以升级，而 `@CHDBits` 与 `@OurBits` 会自然分开。

### 替换时机

1. 先按当前源目录名计算新 ISO 目标路径。
2. 如果新目标路径本身已经存在，继续使用现有精确冲突保护，不自动覆盖。
3. 如果新目标不存在，扫描输出目录和已配置的 CD2 成品目录，找到同站点同片的低版本 ISO。
4. 新 ISO 先写入新目标、完成结构校验，并成功转存到 CD2（如启用）。
5. 新版本确认可用后，再清理被替代的低版本 ISO；清理失败时保留旧文件并记录可见警告，不影响新版本的成功状态。
6. 如果只找到更高或相同版本，不做替换并保留现有人工冲突语义。

替换动作只处理明确版本号的旧文件。未标注版本不会被列入清理候选，即使片名和站点相同。

## 自动拉取去重

在 `state["cd2"]` 下增加持久化的自动拉取认领表，认领键为归一化后的 `source_path + dest_dir`。自动拉取流程在调用 CD2 创建任务前先登记 `creating` 状态，成功后改为 `submitted`；创建失败则删除认领并沿用现有失败冷却。

后续扫描优先检查认领表，再检查本地任务状态、CD2 队列和现有记录。已有认领的候选只返回跳过原因，不再次调用 `copy_file`，也不重复写入“自动拉取已创建”日志。任务完成或候选被人工清除时同步更新/删除认领；部署升级时兼容已有 `state.items` 与最近成功拉取记录，避免旧状态重新触发重复任务。

## 异常恢复卡片布局

异常标题区域的文本列增加 `min-w-0`，状态徽标保持可收缩并在必要时截断。标题、异常详情和运维建议使用 `overflow-wrap: anywhere`，同时保留可读的行高和父容器宽度约束。路径仍完整保留在 DOM 文本和 `title` 中，但不会把卡片或页面撑出横向滚动区域。

## 错误处理

- 无法解析站点或版本时，不自动替换，继续显示人工处理建议。
- 新版本生成或校验失败时，旧版本保持不变。
- 新版本已转存但旧文件清理失败时，新版本标记为成功，同时写入旧版本清理失败的 warning。
- 自动拉取 CD2 API 调用失败时释放认领，保留现有失败记录和冷却策略。
- 状态文件缺少新增字段时按空表启动，不影响旧状态读取。

## 测试策略

使用标准库测试和现有 v2 smoke 流程覆盖：

- `V1 -> V2`、`V2 -> V3` 能找到同站点低版本；降级、同版本和无版本不替换。
- 同片不同站点不匹配；同站点无版本与明确版本不匹配。
- 新版本生成失败时旧 ISO 保留，成功后才执行旧版本清理。
- 同一自动拉取候选连续扫描只调用一次 CD2 `copy_file`，人工清除后允许再次创建。
- 异常卡片包含最小宽度和任意位置换行约束，长路径不会形成不可断行布局。

## 影响范围

- 后端：输出目标解析、封装冲突/清理、CD2 自动拉取状态持久化。
- 前端：`workspace.html` 异常恢复卡片的布局类。
- 测试：新增版本匹配、自动拉取认领和布局契约回归覆盖。

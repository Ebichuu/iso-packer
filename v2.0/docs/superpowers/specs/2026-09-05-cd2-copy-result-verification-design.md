# CD2 复制结果确认与上传队列分页设计

> 当前实现说明（2026-09-05）：本文件早期的“远端文件确认、结构校验、缺失结果重试”方案已被 CD2 API 权威状态方案取代。`GetCopyTasks` 的状态、进度和失败字段是复制任务的唯一依据；任务暂时不在当前 API 列表时只保持等待，不访问远端结果，也不由 ISO Packer 推断失败或卡住。

## 问题

CloudDrive2 的 `GetCopyTasks` 只返回当前复制任务。复制任务完成后可能从列表中消失，ISO Packer 不能据此直接认定远端结果已经落地。当前拉取认领记录在这种情况下会长期保持“处理中”，即使本地监控目录和远端目标都没有结果，也不会重新提交复制任务。

同时，CloudDrive2 官方文档说明 `GetUploadFileList` 的 `getAll=true` 当前不支持，上传任务必须使用 `itemsPerPage` 和 `pageNumber` 分页读取。现有调用方式可能漏读上传任务。

## 方案

1. 上传队列使用固定页大小分页读取，直到读完 `totalCount` 或服务端不再返回新条目；保留第一页返回的总字节数和速度统计。
2. 自动和手动拉取认领记录通过 `GetCopyTasks` 读取 API 返回的源路径、目标路径、状态、字节数、文件数和错误信息。
3. API 返回活动任务时，按 API 数据展示进度并保持等待；API 返回明确 `Completed` 时标记复制完成，API 返回明确 `Failed` 时记录复制失败。
4. 当前 API 列表暂时没有对应任务时，只保留认领记录并等待下一次 API 刷新，不使用 `FindFileByPath`、`GetSubFiles`、本地目录存在性或自定义超时推断结果。
5. 复制任务匹配同时使用 API 源路径和目标目录，避免同一片名来自不同站点或不同目标时互相覆盖状态。
6. 上传队列继续过滤所有末级扩展名不是 `.iso` 的条目，`.iso.partial` 和 `.iso..partial` 不参与匹配或完成判定。

## API 边界

- `CopyFile` 的 `FileOperationResult` 只作为提交结果使用，不把提交成功当作文件已落地。
- `GetCopyTasks` 只用于当前任务状态；不依赖它提供历史记录。
- `GetCopyTasks` 是复制任务状态、进度和终态的唯一来源；不以任务消失、文件存在或文件大小代替 API 终态。
- 不通过 CloudDrive2 API 直接上传本机文件，仍由挂载目录和 CloudDrive2 的上传服务负责上传。

## 状态与错误处理

- CD2 API 不可用、权限不足或任务列表读取不完整时，只暂停对应等待流程，不删除本机源目录，不标记为成功或失败。
- 开启云端上传等待时，本机输出 ISO 和源目录在云端明确完成前保留；挂载转存仍只写严格 `.iso` 文件名，不创建可被 CD2 扫描的 `.iso.partial`。
- 本地监控目录只负责发现 CD2 已报告完成后的新源目录，不参与判断复制任务是否完成。
- 分页读取遇到单页异常时，保留已成功读取的队列不能作为完整队列使用，并记录读取错误。
- 复制或下载任务查询接口缺失或读取异常时，队列标记为不完整，不能继续封装。
- 自定义文件操作目标只能位于已配置的监控、输出或 CD2 挂载根目录内；启用挂载保护时，CD2 成品目录不能越过挂载根目录。
- `genisoimage`、`xorriso` 和挂载转存均有总时长/无进展保护，避免单个 I/O 或校验调用永久占用封装 worker。
- 本机生成 ISO 阶段允许取消当前 `genisoimage`；取消不会删除源目录，`.partial` 仍按异常恢复流程清理。

## 验收

- 使用 `getAll=False` 分页读取多个上传任务，全部严格 `.iso` 条目都能被收集，非 ISO 条目被过滤。
- 复制任务存在时，认领记录展示 API 返回的进度；API 明确完成或失败时分别进入对应终态。
- 复制任务暂时从当前任务列表消失时，认领记录保持等待，不访问远端结果，也不会重复提交。
- 上传任务曾出现但随后消失时，继续保持等待；只有 API 明确完成或失败才改变状态。
- 失败/取消复制或下载任务即使带有 100% 进度，也不会进入完成状态。
- 现有 ISO 转存、上传监控、路径匹配和非 ISO 拒绝测试继续通过。

## 变更历史

### 2026-09-05 - 落实复制结果确认

**变更内容**: 使用 `FindFileByPath` 与强制刷新目录列表确认 CD2 复制目标，同时确认本地挂载结果；上传队列改为官方分页读取，并暂停不完整队列的误报超时。

**变更理由**: `GetCopyTasks` 在复制任务完成后可能不再返回任务，不能把任务消失当作文件已落地；`GetUploadFileList` 的全量模式在当前 API 中不支持，可能漏掉后续上传任务。

**影响范围**: CD2 自动拉取认领、远端候选状态、上传队列监控和相关回归测试。

**决策依据**: 远端存在且本地挂载可见才算拉取完成；两者都缺失时仅自动重试一次，远端存在但本地不可见则保留失败记录，避免重复复制或误删除源数据。

### 2026-09-05 - 以 CD2 API 状态为唯一任务依据

**变更内容**: 移除上传无进展计时、队列缺失计时、复制结果目录校验和缺失结果自动重试；复制和上传仅依据 CD2 API 的明确状态处理，暂时缺少任务时保持等待；复制任务匹配增加目标目录隔离，并兼容恢复旧的本地误报失败记录。

**变更理由**: CD2 已提供任务进度和终态接口，ISO Packer 不应自行判断任务是否卡住、任务是否消失或文件是否已经落地。

### 2026-09-05 - 收紧异常完成判定

**变更内容**: 上传任务从队列消失不再直接标记为已交付；手动拉取也持久化认领并等待远端与本地结果确认；失败/取消状态优先于进度字段；复制和下载队列读取不完整时阻止封装。

**变更理由**: 队列消失、100% 进度和空列表都不能单独证明任务成功，必须避免异常恢复路径误删文件或提前生成 ISO。

**影响范围**: CD2 上传监控、自动/手动拉取状态、封装前门禁和相关回归测试。

### 2026-09-05 - 增加结构与 I/O 边界保护

**变更内容**: 拉取完成判定增加远端和本地原盘结构检查；限制自定义文件操作和 CD2 成品路径；为封装、ISO 校验和转存增加超时及无进展保护；增加本机封装取消入口；GitHub Actions 在镜像构建前执行测试门禁。

**变更理由**: 目录刚创建或底层 I/O 卡住时，单纯检查路径存在会导致任务提前完成或 worker 长时间不可操作。

**影响范围**: CD2 拉取恢复、文件浏览操作、ISO 封装/校验/转存和镜像发布流程。
